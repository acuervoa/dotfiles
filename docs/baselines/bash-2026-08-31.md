# Baseline de Bash — 2026-08-31

## Entorno

- Sistema: Arch Linux + i3 sobre X11.
- Shell: `/usr/bin/bash` 5.3.15.
- Terminal: Kitty; dentro de tmux, `TERM=tmux-256color`.
- Editor: `nvim` mediante `EDITOR` y `VISUAL`.
- Dotfiles gestionados con GNU Stow desde `stow/bash`.
- Estado Git al crear el baseline: `main` alineada con `origin/main`, sin cambios.

## Topología cargada

- `~/.profile` define entorno general, Cargo, Juliaup y `PROJECTS_ROOT`.
- `~/.bash_profile` carga `.profile` y `.bashrc`; además contiene bloques duplicados de Juliaup y PATH local.
- `~/.bashrc` carga aliases, `bash_lib`, completado, ble.sh si existe, Atuin, zoxide, direnv, Starship, mise, fnm, OpenClaw y configuración local.
- `~/.bash_lib/bash_lib.sh` importa los módulos `core`, `nav`, `docker`, `git`, `misc` y `ai`.
- `~/.bash_functions` existe, pero está vacío.

## Hallazgos priorizados

### P0 — Clipboard Bash incoherente con la sesión gráfica

`.bashrc` selecciona `wl-copy` sólo porque el binario está instalado. En la sesión confirmada (`X11`, `DISPLAY=:0`, `WAYLAND_DISPLAY` vacío), el backend correcto es `xclip -selection clipboard`.

Estado observado:

```text
pbcopy() { wl-copy; }
pbpaste() { wl-paste; }
```

`cb` sí contiene una detección adicional del socket Wayland y evita este error; conviene unificar ambos contratos.

### P1 — Inicialización duplicada de entorno

Juliaup y `$HOME/.local/bin` aparecen en `.profile`, `.bash_profile` y/o `.bashrc`. Aunque parte de Juliaup es idempotente, la topología actual hace difícil razonar sobre el orden y favorece duplicados del PATH.

### P1 — Arranque pesado y no medido por fases

El shell evalúa múltiples inicializadores externos (`atuin`, `zoxide`, `direnv`, `starship`, `mise`, `fnm`) y carga completados. Falta una política explícita entre “siempre disponible”, “sólo en TTY interactiva” y “carga diferida”. No se cambia todavía hasta medir una terminal real.

### P2 — Superficie grande de comandos sin mapa de ownership

Hay funciones útiles para Git, Docker, navegación, QA, servidores y AI, pero también nombres de una letra (`p`, `r`, `y`, `n`) con riesgo de colisión y memoria muscular inconsistente. Conviene clasificar comandos canónicos, aliases de compatibilidad y helpers internos antes de renombrar.

### P2 — Configuración local fuera del grafo de Stow

`~/.bashrc_local` es intencionadamente local y no versionado, pero hoy añade PATH (`$HOME/bin`) sin deduplicación propia. Debe permanecer como escape hatch, con un contrato documentado.

## No modificar en esta fase

- tmux, i3, Kitty, Starship o el historial del usuario.
- `.bashrc_local` salvo para observar su interacción.
- Nombres de funciones/aliases hasta cerrar el mapa de uso real.
- Autoarranque de AgentMemory; sólo se registra como integración con posible coste de arranque.

## Primera fase recomendada

1. Corregir la selección del clipboard de Bash por protocolo activo, manteniendo `cb` y tmux coherentes.
2. Hacer la carga de perfil/PATH idempotente con un único owner por responsabilidad.
3. Medir de nuevo en una terminal Kitty real y comparar arranque limpio/reload.
4. Auditar y documentar la gramática de comandos canónicos antes de cualquier renombrado.
