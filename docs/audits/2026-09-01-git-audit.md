## Hallazgos

### Hooks fuera del checkout

Los hooks versionados viven en `stow/git/.git-hooks`, pero Git los activa
mediante `~/.git-hooks`. Esto funciona en la máquina actual, aunque un clone
limpio no hereda automáticamente el hook path ni sus permisos. El ownership
del hook sí es trazable, pero la instalación no es autosuficiente.

Recomendación: documentar o automatizar la instalación del hook path en el
bootstrap, sin duplicar hooks ni mover la lógica fuera de su owner versionado.

### Ramas locales antiguas

Las ramas `chrore/pre-refactor-shell-20251116`, `feat/newTmux`,
`refactor/productividad-arch-2026-01` y `tmux-key-grammar` están alcanzadas
por `main`. `tmux-key-grammar` conserva además un worktree activo en
`.config/superpowers/worktrees`.

No se deben borrar automáticamente: primero hay que confirmar que no queda
trabajo útil en el worktree y que el usuario quiere retirar esas referencias.

### Objetos dangling

`git fsck --full` informa commits, trees y blobs dangling, sin corrupción.
Son compatibles con operaciones previas de worktrees/amend y no afectan a
las referencias publicadas. No se ejecutará `git prune` como parte de esta
auditoría.

### Check global pendiente

`scripts/check.sh` falla por `SC2034` en la variable local `line` de
`scripts/generate_bash_shortcuts.sh`. Esto queda fuera de `stow/bash` y no
afecta a la configuración inicial ya validada. Debe corregirse o justificarse
en una fase posterior para que el check global sea verde.

### Firmas

No hay configuración activa de firma GPG/SSH para commits o tags; el tag de
release es anotado, no firmado. No bloquea esta release, pero es una mejora
de confianza de supply chain si el repositorio se va a distribuir o desplegar
en más máquinas.

## Próximos pasos sin intervención manual
